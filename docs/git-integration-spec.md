## 1. 背景と目的

- 両ツールの git 対応を先送りしてきたが、主用途が**エージェントとの作業ループ内**（エージェントが編集 → 人間がレビュー → エージェントが修正）に確定したため追加する
- **akapen**: レビュー時に「元々何が書かれていたか」（変更前の内容）を正確に見せたい
- **ashiato**: git のサインを活用して「いま何をレビューすべきか」を切り出したい

## 2. 設計原則

| # | 原則 | 内容 |
|---|---|---|
| P1 | 非 git 環境の完全維持 | git 連携は「git リポジトリ内で起動した場合のみ有効」なアドオン。git なし・リポジトリ外では現行の振る舞いを一切変えない |
| P2 | 情報を増やさない | 表示要素の追加は最小限。既存の表現（DIM など）と融合させる |
| P3 | 行追跡・永続化しない | コメントは「その瞬間のエージェントへの伝言」。位置ずれは追わない。git notes 的な永続化もなし |
| P4 | スナップショット方式 | git 情報は起動時に取得。編集中のファイルと diff が食い違っても問題にしない |

## 3. akapen

### 3-1. 変更行マーク（案A）

- 起動時・リロード時に `git diff -U0 HEAD -- <file>` を取得し、追加・変更行にマーク表示（コンテキスト 0: 3-4 の hunk 粒度を参照）
- 削除行は**位置マークのみ**（内容は表示しない）。中身は 3-2 のトグルで確認する。マークの語彙は 3-4 で確定

### 3-2. old side トグル（案B）

- `o` キー: カーソルのある **hunk**を変更前表示に切替（もう一度で new に戻る）
- 基準は**スコープ従属**（3-4）: `git` = HEAD、`last` = リロード前。diff 取得は ref を引数に取る構造で、将来の世代移動（HEAD^ 等）も後付け可能
- hunk 内で行数が変わっても表示は hunk 内に閉じる。hunk の 3 形態（書き換え / 純削除 / 純追加）ごとの挙動は 3-4 で確定

### 3-3. やらないこと

- word diff（案C / 行内差分）
- 行追跡
- コミットへのコメント紐付け・永続化

### 3-4. diff スコープ（2026-08-09 確定・実装済み）

**方針**: 「diff スコープ」を導入し、マーク・カウント・old side・ナビゲーションのすべてをスコープに従属させる。

| スコープ | 意味 | タイトルカウント | `o` old side の基準 |
|---|---|---|---|
| `last` | 前回ロードからの変化（エージェントの今回分） | `+N/-M`（マークと同じ diff から算出・正確） | リロード前の内容（合成 hunk が保持、ファイル全体の 1 世代保持は不要） |
| `git` | 未コミット全体 vs HEAD | `g+K/-L`（+K 緑・-L 赤。hunk 集計・正確） | HEAD |
| `off` | マークなし | なし | 無効 |

**`both`（重ね表示）は廃止**（2026-08-09）: DIM はターミナル依存で脆く、3 記号 × solid/DIM の 6 視覚状態は P2 に反する。用途は `m` での last↔git 切替で代替できる。

#### スコープの状態遷移

- 初期値: git リポジトリ内 = `git`、リポジトリ外 = `last`（P1: 非 git の見た目を変えない）
- `m` でサイクル: リポジトリ内 `last → git → off`、外 `last ↔ off`。スコープはファイルごと（`FileState`）に保持
- **自動遷移（イベント駆動）**: 内容が実際に変わる reload で `git → last` に切替。ただし
  - `e`（$EDITOR）経由の reload は対象外（自分の編集は採点対象ではない）
  - ⚡ エピソード中にユーザーが `m` を押していたら上書きしない（ピン）。ピンは次の ⚡ 検知でリセット（エピソード単位）
  - `last` / `off` は無条件維持
- reply モード（`--reply`）: スコープ機構ごと無効（diff もバッジも出さない）
- フッター右端に `m:last` 等のバッジ常時表示（git 外の `last` と reply では非表示）
- ⚡ pending はタイトルカウントより優先

#### マーク語彙

**source モード（3 分類）**:

| マーク | 意味 |
|---|---|
| 緑 `+` | 純追加行（旧内容なし） |
| 黄 `~` | 書き換え行（削除+追加のペア。`o` で旧内容が見られる） |
| 赤 `▀` | この行の**上**で削除があった位置マーク（旧 `-` は diff 記号と意味が逆で誤読の元のため廃止） |

- 追加/書き換えの分解: hunk 内で deletes と adds の先頭 min(D,A) 個のペアを「書き換え」、余りを「純追加」（gitgutter 方式、`Diff::added_modified`）
- 行番号色: 追加・書き換え=緑（黄はコメント行の色と衝突するため使わない）、削除位置=赤

**view モード（2 分類のまま）**: 緑 `▌`（追加∪書き換え）/ 赤 `▀`（削除位置、wrap 行は最初の表示行のみ）。段落 merge で行単位の区別が原理的に曖昧になるため 3 分類は持ち込まない。

**カーソル色の継承**: カーソル `>` はグリフを維持したまま下のマークの色を継承（追加=LightGreen、書き換え=LightYellow、削除位置=LightRed、いずれも BOLD。無マーク行は LightCyan）。1 行 hunk でもカーソルを乗せたままマークが読める。

#### hunk の粒度と可視化

- **git diff は `-U0`（コンテキスト 0）で取得**: 「接する変更は必ず同一 hunk」なので**連続マーク行のかたまり = 1 hunk** が常に成立し、hunk 境界 = マークの切れ目になる。reload 系の合成 diff と同一粒度
- 内部規約: 純削除 hunk の `new_start` は「削除位置 + 1」（git の -U0 素出力から load 時に正規化。先頭削除の `+0,0` はそのまま）。合成 diff（`synthesize_diff`）も同一規約・new 位置順ソート
- **カーソル所属 hunk のマーク強調**: カーソルが hunk 内にある間、その hunk のマークが太字+明色になる（= `o` で裏返る範囲の事前可視化）。スコープ従属
- フッターに hunk ヒント: hunk 内で `hunk L29-33 +1/-2 · o old side`、hunk 外の削除マーク行で `-N deleted above · o: old side`（reload 系のみで数が取れない場合は数なし）

#### `o` old side の挙動（hunk の 3 形態で定義）

| hunk | `o` の動作 |
|---|---|
| 書き換え | マーク行のかたまりを旧内容に置換表示 |
| 純削除 | `▀` の位置に削除された行を**挿入**表示（owner 行は残る） |
| 純追加 | 開かない。フラッシュ `added lines — nothing here before`（追加行に「変更前」は存在しない） |

- 基準はスコープ従属: `last` = リロード前（フラッシュ `old side vs last load`）、`git` = HEAD、`off` = 無効
- `m` でスコープを切り替えたら開いている old side は強制クローズ（hunk index が別 diff を指すため）
- untracked ファイル: git スコープでは `o` 無効。last スコープでは合成 diff で有効

#### ナビゲーション・changes タブ・コメント

- F7 / `]c` / `n` / `N` と changes タブ（`l`）はスコープの diff の hunk を歩く。`off` はフラッシュ `marks off — m: cycle scopes`
- `last` スコープの changes タブ: reload していないファイルはエントリなし（空表示に `no reload changes yet — r reloads`）
- untracked × git スコープ: **マークなし**（全行マークはノイズ）。changes タブの Untracked 行は残る
- **削除マーク行での素の `c`**（選択なし 1 行コメント）: その行に削除を落とす hunk の生 diff をスニペットとして export に添付（現在行のスニペットだけでは削除への言及だと伝わらないため）。生 unified diff はエージェントに最も正確に伝わる形式であり、自然言語の注釈は付けない
- git 外での F7/n: reload diff をナビする（従来は「not in a git repository」でエラー。スコープ導入に伴う意図的な機能追加 — P1 の「見た目を変えない」は維持）

使い分け（ユーザーストーリー）:

1. エージェントが修正 → ⚡ → `r` → 自動で `last` =「今回の宿題の採点」
2. 一段落ついてコミット前 → `m` で `git` = 未コミット全体の最終確認（`+K` 緑 / `-L` 赤で規模がひと目）

実装メモ:

- reload 系 diff は `git::Diff` 構造に正規化済み（`synthesize_diff`）。マーク・カウント・old side・ナビの下流は git 系と完全共通
- 旧 `line_change_counts`（prefix/suffix 近似）は廃止 — カウントは常にマークと同源
- サイクルキーは `m`（marks）で確定（`d` は delete で使用中）

## 4. ashiato

### 4-1. 未コミット表示

- 未コミット変更のあるファイル: 行の右側に `+N -M` を薄く表示（変更規模と未コミットの目印を1要素に融合）
- コミット済み: プラスマイナスなし + 時間表示を DIM
- バッジ・色は追加しない

### 4-2. フィルタ

- `u` キー: 「未コミット変更のあるファイルのみ」表示トグル
- `--filter` は現行のまま（パス部分一致）

### 4-3. 非 git 環境

- プラスマイナス非表示・`u` 無効（= 現行動作）
