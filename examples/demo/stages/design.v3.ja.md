# driftwatch 設計書

> 第 3 稿 — 2 回目のレビューを受けて改稿。

## 1. 概要

**driftwatch** は、*構成のずれ*を見つける小さな CLI である。ずれとは、宣言した状態（YAML のマニフェスト）と、稼働中のマシンの実際の状態との差のことだ。両方を読み、突き合わせ、報告する。

driftwatch はシステムに一切手を加えない。読み取り専用に徹する —報告はするが、直しはしない。

## 2. 構成

| 部品       | 役割                                           |
| ---------- | ---------------------------------------------- |
| `manifest` | YAML から宣言した状態を読む                    |
| `probe`    | 稼働中の状態を集める（ファイル・サービス・ポート） |
| `differ`   | 宣言と実際の差を構造的に取る                   |
| `reporter` | 差をテキスト・JSON・終了コードで出す           |

部品はそれぞれ独立したモジュールで、書き換え可能な状態を共有しない。流れは `manifest → probe → differ → reporter` の一方向だけである。

## 3. 変化の検知

driftwatch はイベント駆動で動く。OS のファイル監視（macOS は FSEvents、Linux は inotify）を購読し、実際に変わった対象だけを調べ直す。監視は1 つですべての対象を受け持つので、ファイルが増えても負荷は増えない。

ファイル監視の API が無い環境では、一定の間隔（既定 5 秒）で見に行く方式に切り替える。これはあくまで代替であり、本来の設計ではない。

## 4. CLI

```console
$ driftwatch check manifest.yaml          # 人が読むための報告
$ driftwatch check manifest.yaml --json   # 機械が読むための出力
$ driftwatch watch manifest.yaml          # 常駐して、ずれをその場で報告
```

`check` はずれを見つけると 0 以外で終了するので、CI パイプラインやcron ジョブにそのまま差し込める。

## 5. やらないこと

ずれを直すことは範囲外とする。直すにはシステムへの書き込みが要り、1 節の読み取り専用の約束と矛盾するからだ。直す仕組みが欲しい人は、使い慣れた構成管理ツールと driftwatch を組み合わせてほしい。
