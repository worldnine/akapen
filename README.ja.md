# akapen

**akapen**（赤ペン）— エージェントの宿題に赤を入れる。

English README is [here](README.md).

エージェントが 2,000 行の設計書を書いてきた。3 章が間違っていて、1 箇所の例が紛らわしくて、5 章の口調が変。ここから「全部説明する長文プロンプト」を書くか（ニュアンスは薄れる）、エディタで手書き注釈を入れるか（行番号は伝わるが、エディタはこの仕事のためにあるわけではない）。

先生は生徒の作文を書き直さない。赤ペンで印をつけて返す。akapen は、エージェントの宿題への赤ペン。エージェントが生きているターミナルの中で。

## ループ

```
agent が書く → 読む → 印をつける → s で送る → agent が直す → ⚡ → r で読込 → 確認する
```

ターミナル上でファイルを「きれいに読む」→「行を選んでコメント」→「送信」し、文書から一歩も出ずにレビューループを一周させる。エージェントがファイルを編集すると akapen が気づき（`⚡`）、新しい草案が**緑 = 変わった場所・赤 = 消えた場所**のマーク付きで届く。`n`/`N` で差分を巡回し、まだ直っていない箇所にコメントできる。ファイルは絶対に書き換えない。コメントはクリップボード・stdout・send コマンドのどれかで外へ出る。

## 採点簿 — 文書タイムマシン

赤ペンがフェアであるためには、「印をつけた箇所をちゃんと直したか」を確認できなければならない。akapen はエージェントが生んだ**全草案**（Git コミットと上限付きローカルスナップショットの一本のタイムライン）を保持し、レンダリングされたまま `←`/`→` で遡れる。レビューベースラインは「あなたが採点した版」。緑/赤のマークは、そのベースラインと表示中のどの世代を比べても出る。コメントは書かれたときの草案に固定され、リビジョンと一緒にエージェントへ届く。Git 管理は必須ではない。

新しい版より前の版が良かったら、遡ってその箇所にコメントするだけ — 「この草案の方がよかった」— リビジョンと当時の本文が添えられて届くので、エージェントは正確にその版へ戻せる。

## 赤ペンの道具

- **2モード・1カーソル**: view モードは Markdown をネイティブ描画（切り詰めず縮む幅適応表・見出し・コードブロック・リンク・footnote・数式・タスクリスト）、source モードは行番号 + syntect ハイライト（100言語以上）。選択とコメントは両モードで完全に同じ操作
- **どこにでもコメント**: `v` で選択、`c` でコメント。コメントは参照行の直下にインラインカードとして残る
- **リプライモード**: `--reply` で akapen はエージェントの*会話出力*（ファイルに触れず貼られたコード例示・markdown）への即席赤ペンになる
- **常にセッションモード**: 1 ファイルでも 20 ファイルでも同じキーバインド。`]`/`[` で切替、カーソル・選択・モードはファイルごとに保持
- **ターミナルネイティブ**: ANSI パレット追従、two-face テーマ（組み込み32種または任意の `.tmTheme`）、OSC 11 で light/dark 自動検出、`unicode-width` による CJK 対応

## 試す

```sh
cargo install akapen
ashiato . --open-cmd "akapen {} --send-agent"   # ファイルピッカー → 開く → コメント送信ループ
```

`herdr plugin link <このリポジトリ>` でコマンドパレットに `akp.open` 系アクションが登録され、エージェントの直近チャットメッセージを akapen で開ける。

[herdr-reviewr](https://github.com/persiyanov/herdr-reviewr) の行コメント体験を markdown 向けに最適化した、よりシンプルな実装。1ペイン・2モード切替構成です。

## 二つのモード

- **view モード**（.md 既定）: 組み込みのネイティブレンダラ（tui-markdown / pulldown-cmark）で markdown を描画する読む専用表示。表・見出し・コードブロック・リンク（`ラベル (URL)` 表示）・footnote・数式・タスクリスト・front matter まで描画され、フルカラーです。**表は幅適応型**: パン幅を超えるときは列幅を縮小（各列の最長の分割不能トークンまで）してセルを折り返し、切り詰めず情報を失いません。**行カーソル**（落ち着いたグレー背景）を j/k で移動でき、`v` で範囲選択 → `c` でコメント（**source モードと完全に並列**）。コメントの**範囲全体**には左端に黄色の `▌` マーカーが付き、`n`/`N` でコメントへジャンプできます。**インラインのコメントカードも view に表示され**、コメントの状況が読んでいる最中に分かります
- **source モード**: 生ソース + 行番号 + **syntect ハイライト（全言語対応）**。長い行は画面幅で**折り返し**、折り返し行は**行番号ガターの幅ぶんインデント**されて本文の位置が揃います。タブはターミナルと同じ**8桁タブストップ**に展開して表示されます。行を選んでコメントを追加すると、**選択範囲の最後の行の直下に吹き出しカードとして表示**され、レビュー中もその場に残ります（herdr-reviewr と同じインラインカード方式）

## セッションモード（複数ファイル）

**常にセッションモード**です。1ファイルでも複数ファイルでも同じキーバインドで動作します。

```
akapen <file...> [--send-cmd <cmd>] [--send-agent] [--reply] [--theme <name>] [--ime <off|ascii|jp>]
                    [--light|--dark] [--callback <cmd>] [--esc-quit <auto|always|never>] [--no-fx]
```

- 引数に**1つ以上のファイル**を渡します（yazi の `%S` などから複数選択をそのまま渡せます）
- **`]` / `[`** で次の/前のファイルへ。カーソル・選択・モード（view/source）は**ファイルごとに独立して保持**され、再訪時に復元されます
- タイトルバーに **`1/3 files`** 形式で現在位置を表示（クリックでファイル一覧を開く）
- **`.md` / `.markdown` / `.mdx` のみ view モード可**。それ以外のファイルは source モード固定（Tab は無効）

## 配色について

固定の RGB 色は使わず、**ターミナルの配色に追従**します:

- カーソル行は **ANSI グレーの背景**（bright-black。文字色は変えず、view / source 両モードで同じ落ち着いた見た目）。**view / source 両モードで**左端に `>` マーカーが付き、カーソル位置が分かります。選択範囲も同じグレー背景でハイライトされます
- コメント済み行の **行番号は黄色**（ガターで一目で分かる）。view モードでも左端の黄色 `▌` マーカーで分かります
- 枠・ガター・フッタは ANSI 色（DarkGray / Yellow / Cyan / LightBlue）のみ
- **タイムマシン中の枠は truecolor の紫→シアン グラデーションが回転**（`--fx`、既定オン）:
  過去世代を閲覧している間、枠の一周に滑らかなグラデーションの波が流れます。
  トーストもフェードイン/アウトします。どちらも tachyonfx によるエフェクトで、
  派手さが不要な場合は `--no-fx` で静止した紫枠 + 即時トースト（従来どおり）に戻ります
- シンタックスハイライトは **two-face** のテーマ（`--theme` で切替、既定 `Catppuccin Mocha`。
  light モード時は自動検出・`--light` とも `Solarized (light)`。`--theme` の名前が
  解決できない場合も light/dark に合った既定へフォールバック）。`--theme` には two-face の組み込みテーマ名
  （`Catppuccin Mocha`, `base16-ocean.dark`, `Dracula`, `Nord`, `Solarized (dark)` など 32 種）か
  **`.tmTheme` ファイルのパス**（例: tokyo-night.tmTheme）を渡せます。
  light/dark の UI 色は **OSC 11 でターミナル背景を自動検出**（`--light` / `--dark` で
  明示指定が最優先、応答しないターミナルは dark）

view mode の色も**すべて `--theme` のテーマから解決**されます: 見出し・リンク・引用・
インラインコードはテーマの markdown スコープ色、コードブロックは同じテーマを
.tmTheme に往復させて描画します。テーマに該当スコープの色定義が無い構文だけが
ANSI パレットの既定色にフォールバックします。ソースモードと同じテーマなので、
両モードの色味が揃います。古いスコープ名（`markup.fenced_code.block.markdown` など）で
定義されたテーマでも、現在の文法が出力するスコープ名に自動フォールバックします。

ターミナルのカラーパレットを変更すれば、akapen の **UI の色**（枠・ガター・
コメントバー・選択・カーソル・フッタ）は一緒に変わります。ただし
**シンタックスハイライトはテーマの固定色**なのでパレット変更には追従しません。

### 画面レイアウト

<!-- TODO: 実スクリーンショット画像に差し替える -->

```
 ┌────────────────────────────────────────────────────────┐
 │ ⚡ …/cases/aozora-plan.md  1/3 files  y copy · s send ▌ 3 │ ← タイトル（ファイル中心）
 ├────────────────────────────────────────────────────────┤
 ▌ # 見出し…                                            ▐│
 > print(fibonacci(10))                                 ▐│
 │  ─ comment · 12-14 ────────────────────────────────    │
 │  本文…                                                ▐│
 ├────────────────────────────────────────────────────────┤
 │ [ SOURCE ]  L45/120 · j/k move · c comment · ? help     │ ← フッタ（モード + 位置 + ヒント）
 └────────────────────────────────────────────────────────┘
  （メッセージはフッタ直上の行に一時的に表示: view では枠の下辺と
    同じ行、source では最下行の上。`└── comment added (1 total) ──┘`）
```

- **ページは左端から1文字浮いている**: マージンによって、枠の左端（マーカー列）が
  ターミナルの左端に接触しません。タイトル・フッタのストリップはフル幅のままです
- **マーカー列は左フレームに乗っている**: カーソル行は `>`（太字 LightCyan）、コメント行は
  黄色の `▌` が枠の左端に表示され、マーカーのない行は枠の `│` のままです
- **スクロールバー**: view モードは右フレームの内側1列（右ボーダーを汚さない）、
  source モードは右端の列（フレームがないので端まで寄せる）。コンテンツが画面に収まらない
  ときだけ、ビューポート位置を示す `▐` サムが現れます（ホイールスクロール＝ビューポート移動と
  連動）。**トラックのクリックでジャンプ**、**サムのドラッグでスクラブ**できます
- **本文は枠から左右1文字ずつ浮いている**: マーカーと本文の間に隙間があり（`> print(...)`）、
  右端もボーダーと接触しません。コメントカードや入力バーも同じインセットに揃います

- **タイトルバーはファイルのアイデンティティ**: パス（賢い省略）+ `⚡`（外部編集検知）+
  `1/3 files`（セッション位置）+ 右上の黄色 **`▌ N`**（コメント存在インジケータ。最初の
  コメントで点灯し、送信で消える）。`y copy · s send` は**文脈依存**（コメントが無ければ
  非表示、`--send-cmd` が無ければ `y copy` のみ）
- **モードバッジはフッタ**（ステータスラインの定番配置）: 灰=view / **青=source** /
  **シアン=comment**（コンポーザーの吹き出しと同じ色）/**マゼンタ=select**（`v` で選択中。
  `Esc` で解除、ヒントにも「Esc cancel」と明示）。固定幅なのでモード切替で
  ヒントの位置は動きません
- フッタの位置表示は **`L45/120`**（カーソルのソース行/総行数。% ではなくレビューの
  対象である行が正確に分かる）
- **メッセージは1箇所・下に集約**（フッタ直上の行。vim のメッセージラインの
  位置）: 永続プロンプトと一時トーストが同じ行に描かれ、**プロンプト優先**
  （要アクションの確認が、やがて消えるトーストに隠されません）。行は
  **予約せず**、view モードでは枠の下ボーダーの行（コーナーは残るので
  `└── message ──┘` と読める）、source モードでは最下行の上に描画するだけ
  なので、メッセージの有無でレイアウトは一切動きません。どちらも `Clear`
  で自分の領域だけ上書きします
  - **永続プロンプト（黄）** = 要アクション: q 確認・e 確認・r 確認・
    `file changed — r reload · i ignore`
  - **一時トースト** = 黄=情報（例: `copied 3 comment(s)`）、**赤=操作できない**
    （例: `no comments below`・`view mode unavailable`・送信失敗）。赤トーストのときは
    **BEL ビープ**（`\x07`）も鳴ります — vim と同じ端末標準の「無効操作」シグナルで、
    ベル無効化・visual bell 化はユーザーの端末設定に委ねられます

## キー

| Key | 動作 |
|-----|------|
| ← / →（view / source） | 文書の older / newer へ移動。最古 `1/N` → 現在 `NOW N/N`。入力中は世代だけを高速選択し、最後の入力から300ms後に最終世代を描画 |
| Tab | view ⇄ source を**対称トグル**（**選択は引き継がれる**）。.md 以外は無効 |
| j / k | カーソル移動（選択中は範囲を拡張） |
| g / G | 先頭 / 末尾へ |
| PgUp / PgDn, Ctrl+u / Ctrl+d | 半ページ移動 |
| v | 選択開始（view ではマージ段落の行頭にアンカー） |
| c | 選択範囲（or カーソル行）にコメント入力。**選択範囲が既存コメントと完全一致したら再編集**（本文がプリフィルされ、`edit · 12-14` ラベルで Enter が置換になる） |
| `n` / `N` | 表示中世代とbaselineとの差の、次 / 前の箇所を画面中央付近へ移動 |
| t | タイムラインの詳細リスト（履歴ブラウズ中は下部2行の軸: ◆ 表示中 / ▮ baseline / ● LOCAL / ◼ COMMIT） |
| ] / [ | 次の / 前のファイルへ（1ファイルなら no-op） |
| ? | キーリファレンス |
| r / i | ファイル変更時: 再読込 / 変更を無視 |
| a | NOWでは確認済みにする。過去ではそのLOCAL／COMMITをreview baselineにする。選択中なら解除 |
| F7 / Shift+F7 | 次の / 前の未確認箇所へ移動（`]c` / `[c`、`Alt+j` / `Alt+k` も同じ） |
| `Ctrl+n` / `Ctrl+p` | 次の/前のコメントへジャンプ（旧 `n` / `N` から移動） |
| `Ctrl+o` | ファイルピッカー（旧 `Ctrl+p` から移動） |
| l | 全ファイルのコメント一覧 |
| e | `$EDITOR` でファイル編集（復帰時に再読込し、自分の編集は確認済みにする） |
| y | 全コメントをクリップボードへ（コメントは保持） |
| s | `--send-cmd` で送信（成功時のみクリア。**失敗時はコメント保持**で再送可能） |
| d | カーソル位置のコメントを削除 |
| q | 終了（未送信コメントがあれば確認プロンプト） |
| Esc | 入力中=キャンセル / 選択中=選択解除（**モードは変わらない**。切替は Tab のみ）。`--esc-quit` 有効時（既定 `auto` = `--callback` 指定時のみ。`always` で無条件、`never` で無効化）は、ペンディングが何もないときに q と同じく終了へ進む。未送信コメントがあれば確認プロンプトを挟み、プロンプト中の Esc は q と同じ「確定」（`Esc/q to quit` と表示） |

### オーバーレイ（ミニウインドウ）

| キー | オーバーレイ | 内容 |
|------|------------|------|
| Ctrl+o | ファイル一覧 | 全ファイル（同名は一意になるまでパスを追加）+ コメント数 + view/src タグ + 外部編集の `⚡` + 未確認数 `! N`。現在ファイルは強調表示 |
| l | コメント一覧 | 全ファイルの全コメントを**ファイルごとにグループ化**。行範囲 + 本文を1行で表示 |
| ? | キーリファレンス | 全操作の一覧 |

共通操作: `j/k` で移動（**内容が収まる場合はスクロールせず**、溢れたときだけ追従）、
`Enter` で決定（ファイル切替 / コメントの行へジャンプ＋**全行選択**）、`d` で削除
（コメント一覧）、`Esc` / `q` で閉じる。

### マウス

| 操作 | 効果 |
|---|---|
| ホイール上下（本文） | **画面（ビュー）だけスクロール**（カーソルは動かず、スクロールで画面外に出ても、戻すと元の行にいる） |
| 左クリック（スクロールバー） | その位置へ**ビューをジャンプ**（サムを掴む） |
| 左ドラッグ（スクロールバー） | **サムをドラッグしてスクラブ**（掴んだまま列の外に出ても追従） |
| 左クリック（本文） | その行へカーソル移動（選択は開始しない） |
| 左ドラッグ（本文） | 行範囲を選択（view / source 両モード） |
| 左クリック（タイトルの `▌ N`） | コメント一覧を開く |
| 左クリック（タイトルの `1/3 files`） | ファイル一覧を開く |
| 左クリック（タイトルのパス） | **フルパスをクリップボードにコピー** |
| クリック（オーバーレイ内） | その行を選択。**ダブルクリックで決定**（Enter と同じ） |
| クリック（オーバーレイ外） | オーバーレイを閉じる |
| ホイール（オーバーレイ内） | j/k と同じ移動（収まる場合は動かない） |

選択は**スクロールしても解除されません**（仮想的な選択）。選択行が画面外に
出ても範囲は保持され、スクロールで戻すとグレー背景のまま表示されます。
`Esc` で選択を解除できます。

**カーソルはファイル上の絶対位置**です（herdr-review 方式）。ホイールで
スクロールしてもカーソルは動かず、画面外に出てもスクロールを戻すと元の
行にいます。`j/k` で移動すると画面がカーソルに追従します。

### 文書タイムマシンと未確認レビュー

akapen は各世代を差分ではなく完全な文書として扱います。Git コミットと上限付きの LOCAL スナップショットは一つのタイムラインへ入り、Git は必須ではありません。

ブラウズの見た目も時間の流れとして描かれます: `←`/`→` を押しっぱなしにすると、追加・変更行はLLMストリーミング風に左→右へ現れ、消える行はバックスペース風に右→左へ消えてからレイアウトが畳まれます（ゴーストは背景なしのディム表示）。過去の演出は中立の明度を使い、追加/削除の色は使いません。過去を閲覧している間はページの枠も変わります。

1. エージェントがファイルを編集するとタイトルに `⚡` が出ます。
2. `r` で新しい完全な文書を読み込み、LOCAL 世代として保存します。自動では本文を入れ替えません。
3. タイトルの `! N` と緑の `▌` が、最後の確認済み世代からNOWまでの追加・変更を示します。削除は view モードでは赤の `▀`（位置マーク）、**source モードでは削除された行そのものが赤の `▌` + 赤い帯（緑 `▌` の帯と対になる diff ペア）でインライン表示**されます（行番号は空欄。書き換え行も旧内容が上に出る、baseline との diff 表示）。折り返し表示の行では `▌` が該当行の全行に付くので、左端のマーク列が途切れず一続きの帯として読めます。view でなんとなく差異を感じ、Tab で source に切り替えて細部を確認する使い分けです。source で `n`/`N` が純削除に着地すると削除行が明るく**フォーカス**され、そのまま `c` で削除本文を引用したコメントを付けられます。初回は最初に観測したLOCALをbaselineにし、Gitコミットを暗黙の比較基準にはしません。
4. `r`を繰り返してもbaselineは動かず、未確認箇所は累積します。NOWで`a`を押した時だけ確認済みになります。過去で`a`を押すと、そのLOCAL／COMMITをbaselineとして選び直せます。

`←` / `→` では `NOW`・`LOCAL`・`COMMIT` を一つの時系列として移動します。Markdown は常にレンダリングされた状態を保ち、長押し中は**タイトルバー**のラベルと下部2行の**タイムライン軸**だけが即応し、入力が止まってから最終世代を描画します（軸は ◆ 表示中 / ▮ baseline / ● LOCAL / ◼ COMMIT、NOW は常に右端。baseline より左は確認済みの過去で dim、baseline→NOW は未確認区間。view ではフレーム下辺の行に重ねて描画するのでコンテンツ行は失われません。`t` で全世代の詳細リストを開けます）。ラベルの要約部分は切り詰められるので、履歴閲覧中もパスはタイトルに残ります。同じ内容の LOCAL と Git コミットは一世代へ統合されます。

baselineはタイトルバーの履歴ラベルへ常に`base N/M`として併記し（フッタは `← older · newer →` のナビのみ）、その世代を表示しているときは`BASELINE`と明示します。緑／赤のmarksはNOWだけでなく、どの過去世代でもbaselineから表示中世代までを比較して表示します。過去の比較を見ても、NOWに残っている未確認状態は変わりません。

LOCAL スナップショットは内容ハッシュ単位のgzip圧縮で、リポジトリ外のユーザーキャッシュへ保存します。初期上限は1ファイル32世代、全体256MiBです。NOW、review baseline、未確認期間、コメント参照世代は削除しません。**タイムラインの並びは血統順**です: 各 LOCAL は観測時点の HEAD コミット（parent oid）の直後に置かれ、レビュー中にエージェントがコミットしても順序は実際の経緯と一致します。parent が現在の履歴のどのコミットとも一致しない LOCAL（rebase・別ブランチ由来・非 git）は、Git より新しい側・観測順に置く既知の fallback です。レビューマークは全て行単位です（テーブルの1セル編集は1行だけ、段落の1行編集はその行だけをマークし、ブロック全体は対象にしません）。Markdown以外のUTF-8テキストもsourceモードで同じ履歴・レビューを使い、行単位でマークします。

再読込前のNOWに付けたコメントは消さず、直前のLOCALまたはCOMMIT世代へ固定します。エージェントへ渡す補助情報は参照世代、解決済みの絶対ファイルパス、行範囲、引用本文だけで、diffやhunkは含めません。

- `i` は現在のon-disk状態を無視し、次の編集まで `⚡` を消します
- `e` で行った自分自身の編集は、復帰・再読込後に自動で確認済みになります
- コメント入力中は変更検知を止め、入力中の文書を入れ替えません

### インラインコメントバー（上下罫線のみ・フル幅）

`c` を押すと、選択範囲（またはカーソル行）の**最後の行の直下**に入力バーが
インラインで開きます。Enter で確定すると、同じ位置に保存済みコメントの
バーが表示され、そのまま画面に残ります。

吹き出しの**上下の罫線だけを残し、左右の縦罫線を外した**形で、ラインが
画面の左右端まで突き抜けます。背景色は塗らず、**ラインの色で状態**を表します。

```
>  3 これは**太字**と*斜体*と `コード` を含む日本語の文章です。
 comment · 1-3 ──────────────────────────────────────────────────
 この見出し、タイトルをもう少し具体的に
──────────────────────────────────────────────────────────────────
```

- 上ラインの左端にタイトル（行範囲、例 `1-3`）
- **確定後はグレーのライン + 黄色タイトル**（ANSI DarkGray / Yellow）
- **入力中はシアンのライン**（区別しやすい）。**再編集時は `edit · 1-3` ラベル**で、
  元のカードは隠れてコンポーザーだけが表示されます（2段にならない）
- 本文は折返しで自動的に伸び、複数のコメントはそれぞれの行の下に積み重なります。`d` で削除するとバーも消えます

**入力ソースを自動制御します（macOS。`--ime <off|ascii|jp>`）**: コマンドモード
（view / source）では**常に ASCII に固定**し、起動時に現在の入力ソースを保存・
終了時に復元します。コメント入力後の j/k 移動が IME に吸われることがありません。
デフォルトの `ascii` は中立で、入力中（composer）はユーザーの IME 状態のまま
（英語コメントもそのまま打てます）。日本語コメント派は `--ime=jp` で、入力モードを
開くと日本語へ自動切替されます。`off` で無効化。Carbon TIS API を使う Swift ヘルパを
初回のみ `~/.cache/akapen/ime` にビルドします（swiftc が無い環境では自動的に無効化）。

**入力中はカーソルがバー内に表示されます**: ターミナルの実カーソルは
非表示にし（モダンな TUI の標準方式。Hermes / pi.dev と同じ）、挿入位置に
`▏` を描画します。実カーソルを出さないため、日本語 IME の変換確定による
カーソルずれが起きません。macOS の IME 変換ウィンドウは論理カーソル位置
（毎フレーム更新）にインライン表示されるので、変換もバー内で行われます。

**入力中のテキストカーソル移動**: `←`/`→` で1文字、`↑`/`↓` で論理行間
（文字カラムを保持）、`Home`/`End`（または readline 風の `Ctrl+a`/`Ctrl+e`）で
行頭/行末へ移動できます。挿入・`Backspace`・`Delete` はカーソル位置に作用します。
再編集（範囲一致の `c`）でプリフィルされた本文も、末尾から戻って途中を直せます。

**枠線はモードの見た目の署名です**: view は枠あり（読むための「ページ」）、
source は枠なし（タイトルバーとフッタ以外の全行・全桁をソースに使えるので、
スマホなどの狭い画面で有利）。

### 出力形式（reviewr 互換 + スニペットに行番号プレフィックス）

コメント1件 = 過去の場合の `Revision` + location + 行番号付きスニペット + コメント本文。複数コメントは
ファイル・開始行順にソートされ、ブロック間は空行1つで区切られます。

```
path/to/file.md:12-14
12: 行12のテキスト
13:
14: 行14のテキスト
コメント本文
```

スニペットの各行には実ファイルの行番号 + `: ` が前置されるため、選択範囲に
空行が含まれても「13: 」のように番号付きで残り、ブロック区切りの空行と
判別できます。

### 送信（`s` / `--send-cmd` / `--send-agent`）

`y` は**コピーのみ**（コメント保持）。`s` は**送達専用**で、次のどちらかで送ります:

**`--send-agent`（herdr 自動解決・おすすめ）**: herdr ペイン内で起動すると、
**現在のタブ内の唯一の agent**（いなければワークスペースの唯一の agent）を自動で探して
`herdr agent prompt <pane> <text>` で送信します。テキストは argv 直接渡しなので
（シェル非経由）、コメントに `"` や `$` が含まれても壊れません。

```bash
# herdr ペイン内で起動するだけ。タブに agent が1つならそれへ
akapen %S --send-agent
```

**`--send-cmd <cmd>`（汎用）**: フォーマット済みテキストをコマンドの **stdin にパイプ**します。

## リプライモード — エージェントの会話出力に赤ペン（akp）

`--reply` は akapen を「エージェントが会話中に貼ったコード例示・markdown」への即席赤ペンに変えます（ファイルには一切触れない）:

```sh
akapen ... --send-agent --reply
```

- **送信形式**: ファイル/行番号の参照を省き、選択スニペットを GitHub 風の `> ` 引用にする。コメントは空行の後に置く（CommonMark の lazy continuation で引用に飲み込まれないため）。**バッチ送信時は引用に番号**（`1. > 引用` + インデントしたコメント）が付き、受信エージェントは「順番に対応すべき個別指摘のリスト」と読める。番号は `> ` マーカーの**前**にあるので、引用内容にリスト番号が含まれても衝突しない
- **自動リロード・diff なし**: ドキュメントが変わると自動でリロードされ、diff は計算しない（reply モードのドキュメントは1メッセージ丸ごと置換されるため）
- **reply 用 UI**: タイトルは `reply`（一時ファイルパスは出さない）、`]`/`[` で直近メッセージを移動、`e`（編集）とファイルピッカーは無効化

`scripts/akp`（`akp` として配置）がドキュメント一式を組み立てます: カレントタブの唯一エージェントを解決し、セッショントランスクリプト（pi/claude/codex はセッションID検索の JSONL、hermes は SQLite）から直近の text を含むアシスタントメッセージを抽出して akapen で開きます。Codex のタイムスタンプ付き rollout ファイルと `response_item` / `output_text` 形式にも対応しています。再実行するとその場でリフレッシュされます。

### herdr プラグイン

このリポジトリはそのまま [herdr プラグイン](herdr-plugin.toml) です: `herdr plugin link <このリポジトリ>` で3つのアクション — `akp.open`（下分割）/ `akp.open-side`（横分割）/ `akp.open-float`（セッションポップアップ）— が登録され、コマンドパレットから選べます。各配置はトグル（タブに1つ、akapen を抜けると pane ごと自動クローズ）で、分割はフォーカス中 pane ではなく**タブのエージェント pane** 基準に行われます。

**流儀**: herdr 連携コードはツールのリポジトリに plugin として同居させる（`herdr plugin link`）。新規連携は `~/.local/bin` にスクリプトを置かず、リポジトリの `herdr-plugin.toml` に追加すること。
特定の agent に固定で送りたい場合や、herdr 以外の宛先に使います:

```bash
# 特定 pane へ（引用符を含むコメントでも安全な渡し方）
akapen %S --send-cmd 'xargs -0 -I{} herdr agent prompt wY:p1K {}'
# ファイルに残す
akapen %S --send-cmd 'cat >> review.txt'
```

- **送信成功** → トースト + コメントクリア（送達済み）
- **送信失敗**（exit 非零。例: ターゲット不明 / タブに agent が0・複数）→
  `send failed: … · comments kept`。**コメントは保持**され、対象を直して再送できます。
  q 時は未送信コメントの確認が働きます
- `--send-cmd` / `--send-agent` のどちらもなしの `s` は no-op（トーストで `y` を案内）

### hunk 連携（akapen のコメントを hunk の diff ビューへ注入）

これは外部ツールへの互換アダプタです。akapen本体はhunkを保持・表示・出力しません。

[modem-dev/hunk](https://github.com/modem-dev/hunk) はエージェントの変更セットをレビューする
diff ビューア。akapen のコメント（現在ファイルの行番号）は hunk の `hunk diff`
（ワーキングツリー）の **new side の行番号とそのまま一致**するので、変換アダプタ
[`scripts/akapen2hunk`](scripts/akapen2hunk) を `--send-cmd` に挟むだけで
人間の行コメントを hunk のライブセッションにインライン注記として注入できます
（`hunk session comment apply` の stdin JSON に変換）。エージェントは hunk の
skill（`hunk skill path`）経由で `--next-comment` などから拾えます。

```bash
# hunk diff --watch を別ペインで起動した状態で:
akapen doc.md --send-cmd 'akapen2hunk [--repo <root>] [--focus]'
```

- コメント範囲は hunk 側に複数行の概念が無いため `newLine=start` にピン留め、本文はそのまま summary
- `--repo` 省略時はカレントの git root。`--dry-run` で変換 JSON の確認だけできます
- スニペット行数は location の `start-end` から確定するため、本文が「12: 」で始まっても誤爆しません
- hunk が起動していない / 対象ファイルがレビューに無い場合は exit 非零 → 通常の送信失敗トースト（コメント保持）

hunk の watch モードと akapen の `⚡` 再読込は同じエージェントループの二つの視点
（diff 視点 / ドキュメント視点）で、herdr 二画面（`hunk diff --watch` +
`akapen --send-agent`）で併用するのが自然な流れです。

## 設計

設計上の不変条件とその理由は [docs/internals.md](docs/internals.md) に集約しています。

- Rust + [ratatui](https://ratatui.rs) 0.30（reviewr と同じバージョン）
- view mode は `tui-markdown`（pulldown-cmark）で markdown を ratatui Text に変換し、source モードと同じ幅対応折返しで表示行に展開。サブプロセスなし・リサイズはデバウンス後すぐ再レンダリング
- source モードは行番号 + syntect の行単位ハイライト。**文法はファイルの拡張子から解決**（syntect バンドルの100言語以上。未知の拡張子は Plain Text）。折返し・カーソル・選択範囲の計算は `unicode-width` で行うため、日本語全角文字でも表示が崩れません
- セッションは `files` + ファイルごとの状態（カーソル・選択・モード・変更検知スタンプ）を保持し、`]`/`[` でスワップ
- クリップボード: `pbcopy` → `wl-copy` → `xclip` → `xsel` の順に検出
- コメントはファイルを一切書き換えません（読み取り専用。出力は別チャネル）

### モジュール構成

```
src/main.rs        — エントリ、モード状態機械、イベントループ、描画
src/app.rs         — セッションとファイルごとの状態
src/history.rs     — Git / LOCAL / NOW の統合タイムラインとブロック対応付け
src/snapshot.rs    — 圧縮ローカルスナップショット、review baseline、上限付きGC
src/overlay.rs     — ファイル・コメント・ヘルプのオーバーレイ
src/config.rs      — CLI 引数パース（位置引数=files, --send-cmd, --theme, --ime, --light|--dark, --callback, --esc-quit）
src/render.rs      — ネイティブ markdown レンダリング（tui-markdown → 表示行 + ソース行マッピング）
src/view.rs        — 表示行の保持・スクロール・カーソル
src/source.rs      — ファイル読込、行分割、行番号・幅計算（unicode-width）
src/theme.rs       — OSC 11 背景色検出（ashiato の src/theme.rs とミラー）
src/highlight.rs   — syntect による行ハイライト（拡張子から文法を選択、reviewr から移植）
src/comment.rs     — Comment 構造体、選択状態、コメント追加/削除/再編集、location()
src/export.rs      — 出力ブロック整形 + クリップボード + send-cmd 送信
src/ime.rs         — macOS 入力ソース制御（Swift ヘルパ）
```
