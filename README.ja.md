# akapen

**akapen**（赤ペン）— エージェントの宿題に赤を入れる。

English README is [here](README.md).

行コメント TUI。ターミナル上でファイルを「きれいに読む」→「行を選んでコメント」→「送信」するスタンドアロンアプリ。

[herdr-reviewr](https://github.com/persiyanov/herdr-reviewr) の行コメント体験を markdown 向けに最適化した、よりシンプルな実装。1ペイン・2モード切替構成です。

- **view モード**（.md 既定）: 組み込みのネイティブレンダラ（tui-markdown / pulldown-cmark）で markdown を描画する読む専用表示。表・見出し・コードブロック・リンク（`ラベル (URL)` 表示）・footnote・数式・タスクリスト・front matter まで描画され、フルカラーです。**行カーソル**（落ち着いたグレー背景）を j/k で移動でき、`v` で範囲選択 → `c` でコメント（**source モードと完全に並列**）。コメントの**範囲全体**には左端に黄色の `▌` マーカーが付き、`n`/`N` でコメントの塊へジャンプできます。**インラインのコメントカードも view に表示され**、コメントの状況が読んでいる最中に分かります
- **source モード**: 生ソース + 行番号 + **syntect ハイライト（全言語対応）**。長い行は画面幅で**折り返し**、折り返し行は**行番号ガターの幅ぶんインデント**されて本文の位置が揃います。タブはターミナルと同じ**8桁タブストップ**に展開して表示されます。行を選んでコメントを追加すると、**選択範囲の最後の行の直下に吹き出しカードとして表示**され、レビュー中もその場に残ります（herdr-reviewr と同じインラインカード方式）

## セッションモード（複数ファイル）

**常にセッションモード**です。1ファイルでも複数ファイルでも同じキーバインドで動作します。

```
akapen <file...> [--send-cmd <cmd>] [--theme <name>] [--ime <off|ascii|jp>]
                    [--light|--dark] [--callback <cmd>]
```

- 引数に**1つ以上のファイル**を渡します（yazi の `%S` などから複数選択をそのまま渡せます）
- **`]` / `[`** で次の/前のファイルへ。カーソル・選択・モード（view/source）は**ファイルごとに独立して保持**され、再訪時に復元されます
- タイトルバーに **`1/3 files`** 形式で現在位置を表示（クリックでファイル一覧を開く）
- **`.md` / `.markdown` / `.mdx` のみ view モード可**。それ以外のファイルは source モード固定（Tab は無効）

## 配色について

固定の RGB 色は使わず、**ターミナルの配色に追従**します:

- カーソル行は **ANSI グレーの背景**（bright-black。文字色は変えず、view / source 両モードで同じ落ち着いた見た目）。**view / source 両モードで**左端に `>` マーカーが付き、カーソル位置が分かります。選択範囲も同じグレー背景でハイライトされます
- コメント済み行の **行番号は黄色**（ガターで一目で分かる）。view モードでも左端の黄色 `▌` マーカーで分かります
- 枠・ガター・フッタは ANSI 色（DarkGray / Yellow / Cyan / LightBlue）のみ
- シンタックスハイライトは **two-face** のテーマ（`--theme` で切替、既定 `Catppuccin Mocha`。
  light モード時は自動検出・`--light` とも `Solarized (light)`。`--theme` の名前が
  解決できない場合も light/dark に合った既定へフォールバック）。`--theme` には two-face の組み込みテーマ名
  （`Catppuccin Mocha`, `base16-ocean.dark`, `Dracula`, `Nord`, `Solarized (dark)` など 32 種）か
  **`.tmTheme` ファイルのパス**（例: tokyo-night.tmTheme）を渡せます。
  light/dark の UI 色は **OSC 11 でターミナル背景を自動検出**（`--light` / `--dark` で
  明示指定が最優先、応答しないターミナルは dark）

view mode の色も**すべて `--theme` のテーマから解決**されます: 見出し・リンク・引用・
インラインコードはテーマの markdown スコープ色、コードブロックは同じテーマを
.tmTheme に往復させて描画します。テーマに該当スコープの色定義が無い構文だけが
ANSI パレットの既定色にフォールバックします。ソースモードと同じテーマなので、
両モードの色味が揃います。古いスコープ名（`markup.fenced_code.block.markdown` など）で
定義されたテーマでも、現在の文法が出力するスコープ名に自動フォールバックします。

ターミナルのカラーパレットを変更すれば、akapen の **UI の色**（枠・ガター・
コメントバー・選択・カーソル・フッタ）は一緒に変わります。ただし
**シンタックスハイライトはテーマの固定色**なのでパレット変更には追従しません。

### 画面レイアウト

<!-- TODO: 実スクリーンショット画像に差し替える -->

```
┌──────────────────────────────────────────────────────────┐
│ ⚡ …/cases/aozora-plan.md  1/3 files  y copy · s send ▌ 3  │ ← タイトル（ファイル中心）
├──────────────────────────────────────────────────────────┤
│ ▌ # 見出し…                                              │
│  > 行テキスト…                                            │
│  ─ comment · 12-14 ───────────────────────────────────   │
│  本文…                                                    │
├──────────────────────────────────────────────────────────┤
│ [ SOURCE ]  L45/120 · j/k move · v select · c comment · ? help │ ← フッタ（モード + 位置 + ヒント）
└──────────────────────────────────────────────────────────┘
```

- **タイトルバーはファイルのアイデンティティ**: パス（賢い省略）+ `⚡`（外部編集検知）+
  `1/3 files`（セッション位置）+ 右上の黄色 **`▌ N`**（コメント存在インジケータ。最初の
  コメントで点灯し、送信で消える）。`y copy · s send` は**文脈依存**（コメントが無ければ
  非表示、`--send-cmd` が無ければ `y copy` のみ）
- **モードバッジはフッタ**（ステータスラインの定番配置）: 灰=view / **青=source** /
  **シアン=input**（コンポーザーの吹き出しと同じ色）。固定幅なのでモード切替で
  ヒントの位置は動きません
- フッタの位置表示は **`L45/120`**（カーソルのソース行/総行数。% ではなくレビューの
  対象である行が正確に分かる）
- **バナーは2箇所に役割分離**（どちらも `Clear` で自分の領域だけ上書きするので、
  コンテンツは一切押しのけられずスクロールも起きません）:
  - **上部中央 = 永続プロンプト**（要アクション）: q 確認・e 確認・`file changed — r reload · i ignore`（黄）
  - **下部中央（フッタ直上）= 一時トースト**（vim のメッセージラインの位置）: 黄=情報、
    **赤=操作できない**（例: `no comments below`・`view mode unavailable`・送信失敗）。
    赤トーストのときは **BEL ビープ**（`\x07`）も鳴ります — vim と同じ端末標準の
    「無効操作」シグナルで、ベル無効化・visual bell 化はユーザーの端末設定に委ねられます

## インストール / ビルド

```sh
cargo install akapen
```

ソースからビルドする場合:

```sh
cargo build --release
# バイナリ: target/release/akapen
```

依存: 外部バイナリ不要（レンダリングは組み込み）。macOS の IME 自動制御のみ
初回に swiftc でヘルパをビルドします（無ければ自動無効化）。

## キー

| Key | 動作 |
|-----|------|
| Tab | view ⇄ source を**対称トグル**（**選択は引き継がれる**）。.md 以外は無効 |
| j / k | カーソル移動（選択中は範囲を拡張） |
| g / G | 先頭 / 末尾へ |
| PgUp / PgDn, Ctrl+u / Ctrl+d | 半ページ移動 |
| v | 選択開始（view ではマージ段落の行頭にアンカー） |
| c | 選択範囲（or カーソル行）にコメント入力。**選択範囲が既存コメントと完全一致したら再編集**（本文がプリフィルされ、`edit · 12-14` ラベルで Enter が置換になる） |
| n / N | コメントの塊（連続するコメント範囲の和）へジャンプ + **塊全体が選択された状態**になる |
| ] / [ | 次の / 前のファイルへ（1ファイルなら no-op） |
| l | **全コメント一覧**オーバーレイ |
| Ctrl+p | **ファイル一覧**オーバーレイ |
| ? | キーリファレンス |
| r / i | ファイル変更時: 再読込 / 変更を無視 |
| e | `$EDITOR` でファイル編集（未送信コメントがあれば確認） |
| y | 全コメントをクリップボードへ（コメントは保持） |
| s | `--send-cmd` で送信（成功時のみクリア。**失敗時はコメント保持**で再送可能） |
| d | カーソル位置のコメントを削除 |
| q | 終了（未送信コメントがあれば確認プロンプト） |
| Esc | 入力中=キャンセル / 選択中=選択解除（**モードは変わらない**。切替は Tab のみ） |

### オーバーレイ（ミニウインドウ）

| キー | オーバーレイ | 内容 |
|------|------------|------|
| Ctrl+p | ファイル一覧 | 全ファイル（同名は一意になるまでパスを追加）+ コメント数 + view/src タグ + 外部編集の `⚡`（バックグラウンドのファイルも検知）。現在ファイルは強調表示 |
| l | コメント一覧 | 全ファイルの全コメントを**ファイルごとにグループ化**。行範囲 + 本文を1行で表示 |
| ? | キーリファレンス | 全操作の一覧 |

共通操作: `j/k` で移動（**内容が収まる場合はスクロールせず**、溢れたときだけ追従）、
`Enter` で決定（ファイル切替 / コメントの行へジャンプ＋**全行選択**）、`d` で削除
（コメント一覧）、`Esc` / `q` で閉じる。

### マウス

| 操作 | 効果 |
|---|---|
| ホイール上下（本文） | **画面（ビュー）だけスクロール**（カーソルは動かず、スクロールで画面外に出ても、戻すと元の行にいる） |
| 左クリック（本文） | その行へカーソル移動（選択は開始しない） |
| 左ドラッグ（本文） | 行範囲を選択（view / source 両モード） |
| 左クリック（タイトルの `▌ N`） | コメント一覧を開く |
| 左クリック（タイトルの `1/3 files`） | ファイル一覧を開く |
| 左クリック（タイトルのパス） | **フルパスをクリップボードにコピー** |
| クリック（オーバーレイ内） | その行を選択。**ダブルクリックで決定**（Enter と同じ） |
| クリック（オーバーレイ外） | オーバーレイを閉じる |
| ホイール（オーバーレイ内） | j/k と同じ移動（収まる場合は動かない） |

選択は**スクロールしても解除されません**（仮想的な選択）。選択行が画面外に
出ても範囲は保持され、スクロールで戻すとグレー背景のまま表示されます。
`Esc` で選択を解除できます。

**カーソルはファイル上の絶対位置**です（herdr-review 方式）。ホイールで
スクロールしてもカーソルは動かず、画面外に出てもスクロールを戻すと元の
行にいます。`j/k` で移動すると画面がカーソルに追従します。

### エージェント編集の検知と手動再読込

このツールはエージェントループ（コメント送信 → エージェントが md を編集 → 再レビュー）
を想定しています。ファイルが外部から編集されると、**約 300ms のデバウンス後に**
タイトルバッジに **`⚡`** が付き、上部バナーに「**file changed — r reload · i ignore**」と
表示されます:

- **`r` で再読込**（Vim の `:e` と同じ。勝手に内容は入れ替わりません）:
  - タイトルバッジが **`+N/-M`**（追加/削除行数）に変わり、「reloaded (+N/-M)」と表示
  - **変更行がハイライト**されます: 追加/変更された行は緑の `+` ガター + 薄緑背景、
    削除ブロック直後の行は赤の `-` ガター（view モードは緑/赤の `▌` マーカー）。
    次の再読込まで残ります
  - view モードはカーソル位置（割合）を維持したまま再レンダリング。
    source モードはカーソル行番号を維持（行が減った場合は末尾にクランプ）。選択範囲はクリア
  - **現在ファイルのコメントはクリア**されます（旧内容への行アンカーは無効のため。
    他のファイルのコメントは無傷。トーストが「N comment(s) cleared」と報告）
- **`i` で無視**: 現在の on-disk 状態を「見た」と記録し、次の編集まで再通知しません
- **`e` で `$EDITOR` を開いて自分で編集**もできます（TUI をサスペンド → 復帰時に
  自動再読込 + 同じ diff ハイライト。現在ファイルに未送信コメントがあれば確認の上クリア）
- コメント入力中（composer が開いている間）は検知自体を行いません（編集中のコメントを保護）

### インラインコメントバー（上下罫線のみ・フル幅）

`c` を押すと、選択範囲（またはカーソル行）の**最後の行の直下**に入力バーが
インラインで開きます。Enter で確定すると、同じ位置に保存済みコメントの
バーが表示され、そのまま画面に残ります。

吹き出しの**上下の罫線だけを残し、左右の縦罫線を外した**形で、ラインが
画面の左右端まで突き抜けます。背景色は塗らず、**ラインの色で状態**を表します。

```
>  3 これは**太字**と*斜体*と `コード` を含む日本語の文章です。
 comment · 1-3 ──────────────────────────────────────────────────
 この見出し、タイトルをもう少し具体的に
──────────────────────────────────────────────────────────────────
```

- 上ラインの左端にタイトル（行範囲、例 `1-3`）
- **確定後はグレーのライン + 黄色タイトル**（ANSI DarkGray / Yellow）
- **入力中はシアンのライン**（区別しやすい）。**再編集時は `edit · 1-3` ラベル**で、
  元のカードは隠れてコンポーザーだけが表示されます（2段にならない）
- 本文は折返しで自動的に伸び、複数のコメントはそれぞれの行の下に積み重なります。`d` で削除するとバーも消えます

**入力ソースを自動制御します（macOS。`--ime <off|ascii|jp>`）**: コマンドモード
（view / source）では**常に ASCII に固定**し、起動時に現在の入力ソースを保存・
終了時に復元します。コメント入力後の j/k 移動が IME に吸われることがありません。
デフォルトの `ascii` は中立で、入力中（composer）はユーザーの IME 状態のまま
（英語コメントもそのまま打てます）。日本語コメント派は `--ime=jp` で、入力モードを
開くと日本語へ自動切替されます。`off` で無効化。Carbon TIS API を使う Swift ヘルパを
初回のみ `~/.cache/akapen/ime` にビルドします（swiftc が無い環境では自動的に無効化）。

**入力中はカーソルがバー内に表示されます**: ターミナルの実カーソルは
非表示にし（モダンな TUI の標準方式。Hermes / pi.dev と同じ）、挿入位置に
`▏` を描画します。実カーソルを出さないため、日本語 IME の変換確定による
カーソルずれが起きません。macOS の IME 変換ウィンドウは論理カーソル位置
（毎フレーム更新）にインライン表示されるので、変換もバー内で行われます。

**入力中のテキストカーソル移動**: `←`/`→` で1文字、`↑`/`↓` で論理行間
（文字カラムを保持）、`Home`/`End`（または readline 風の `Ctrl+a`/`Ctrl+e`）で
行頭/行末へ移動できます。挿入・`Backspace`・`Delete` はカーソル位置に作用します。
再編集（範囲一致の `c`）でプリフィルされた本文も、末尾から戻って途中を直せます。

**枠線はモードの見た目の署名です**: view は枠あり（読むための「ページ」）、
source は枠なし（タイトルバーとフッタ以外の全行・全桁をソースに使えるので、
スマホなどの狭い画面で有利）。

### 出力形式（reviewr 互換 + スニペットに行番号プレフィックス）

コメント1件 = location + 行番号付きスニペット + コメント本文。複数コメントは
ファイル・開始行順にソートされ、ブロック間は空行1つで区切られます。

```
path/to/file.md:12-14
12: 行12のテキスト
13:
14: 行14のテキスト
コメント本文
```

スニペットの各行には実ファイルの行番号 + `: ` が前置されるため、選択範囲に
空行が含まれても「13: 」のように番号付きで残り、ブロック区切りの空行と
判別できます。

### 送信（`s` / `--send-cmd` / `--send-agent`）

`y` は**コピーのみ**（コメント保持）。`s` は**送達専用**で、次のどちらかで送ります:

**`--send-agent`（herdr 自動解決・おすすめ）**: herdr ペイン内で起動すると、
**現在のタブ内の唯一の agent**（いなければワークスペースの唯一の agent）を自動で探して
`herdr agent prompt <pane> <text>` で送信します。テキストは argv 直接渡しなので
（シェル非経由）、コメントに `"` や `$` が含まれても壊れません。

```bash
# herdr ペイン内で起動するだけ。タブに agent が1つならそれへ
akapen %S --send-agent
```

**`--send-cmd <cmd>`（汎用）**: フォーマット済みテキストをコマンドの **stdin にパイプ**します。
特定の agent に固定で送りたい場合や、herdr 以外の宛先に使います:

```bash
# 特定 pane へ（引用符を含むコメントでも安全な渡し方）
akapen %S --send-cmd 'xargs -0 -I{} herdr agent prompt wY:p1K {}'
# ファイルに残す
akapen %S --send-cmd 'cat >> review.txt'
```

- **送信成功** → トースト + コメントクリア（送達済み）
- **送信失敗**（exit 非零。例: ターゲット不明 / タブに agent が0・複数）→
  `send failed: … · comments kept`。**コメントは保持**され、対象を直して再送できます。
  q 時は未送信コメントの確認が働きます
- `--send-cmd` / `--send-agent` のどちらもなしの `s` は no-op（トーストで `y` を案内）

### hunk 連携（akapen のコメントを hunk の diff ビューへ注入）

[modem-dev/hunk](https://github.com/modem-dev/hunk) はエージェントの変更セットをレビューする
diff ビューア。akapen のコメント（現在ファイルの行番号）は hunk の `hunk diff`
（ワーキングツリー）の **new side の行番号とそのまま一致**するので、変換アダプタ
[`scripts/akapen2hunk`](scripts/akapen2hunk) を `--send-cmd` に挟むだけで
人間の行コメントを hunk のライブセッションにインライン注記として注入できます
（`hunk session comment apply` の stdin JSON に変換）。エージェントは hunk の
skill（`hunk skill path`）経由で `--next-comment` などから拾えます。

```bash
# hunk diff --watch を別ペインで起動した状態で:
akapen doc.md --send-cmd 'akapen2hunk [--repo <root>] [--focus]'
```

- コメント範囲は hunk 側に複数行の概念が無いため `newLine=start` にピン留め、本文はそのまま summary
- `--repo` 省略時はカレントの git root。`--dry-run` で変換 JSON の確認だけできます
- スニペット行数は location の `start-end` から確定するため、本文が「12: 」で始まっても誤爆しません
- hunk が起動していない / 対象ファイルがレビューに無い場合は exit 非零 → 通常の送信失敗トースト（コメント保持）

hunk の watch モードと akapen の `⚡` 再読込は同じエージェントループの二つの視点
（diff 視点 / ドキュメント視点）で、herdr 二画面（`hunk diff --watch` +
`akapen --send-agent`）で併用するのが自然な流れです。

## 設計

設計上の不変条件とその理由は [docs/internals.md](docs/internals.md) に集約しています。

- Rust + [ratatui](https://ratatui.rs) 0.30（reviewr と同じバージョン）
- view mode は `tui-markdown`（pulldown-cmark）で markdown を ratatui Text に変換し、source モードと同じ幅対応折返しで表示行に展開。サブプロセスなし・リサイズはデバウンス後すぐ再レンダリング
- source モードは行番号 + syntect の行単位ハイライト。**文法はファイルの拡張子から解決**（syntect バンドルの100言語以上。未知の拡張子は Plain Text）。折返し・カーソル・選択範囲の計算は `unicode-width` で行うため、日本語全角文字でも表示が崩れません
- セッションは `files` + ファイルごとの状態（カーソル・選択・モード・変更検知スタンプ）を保持し、`]`/`[` でスワップ
- クリップボード: `pbcopy` → `wl-copy` → `xclip` → `xsel` の順に検出
- コメントはファイルを一切書き換えません（読み取り専用。出力は別チャネル）

### モジュール構成

```
src/main.rs        — エントリ、モード状態機械、イベントループ、オーバーレイ、描画
src/config.rs      — CLI 引数パース（位置引数=files, --send-cmd, --theme, --ime, --light|--dark, --callback）
src/render.rs      — ネイティブ markdown レンダリング（tui-markdown → 表示行 + ソース行マッピング）
src/view.rs        — 表示行の保持・スクロール・カーソル
src/source.rs      — ファイル読込、行分割、行番号・幅計算（unicode-width）
src/theme.rs       — OSC 11 背景色検出（ashiato の src/theme.rs とミラー）
src/highlight.rs   — syntect による行ハイライト（拡張子から文法を選択、reviewr から移植）
src/comment.rs     — Comment 構造体、選択状態、コメント追加/削除/再編集、location()
src/export.rs      — 出力ブロック整形 + クリップボード + send-cmd 送信
src/ime.rs         — macOS 入力ソース制御（Swift ヘルパ）
```
