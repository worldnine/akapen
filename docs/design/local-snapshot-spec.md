# akapen ローカルスナップショット／レビュー仕様 v0.1

ステータス: v0.1 基本機能を実装済み（2026-08-10）

この文書は、現在の Git diff / hunk / diff scope を、文書スナップショットを中心にした
レビュー方式へ置き換えた実装仕様である。
`git-integration-spec.md` の akapen に関する記述は本文書で置き換えられた。

実装済みの v0.1 は、LOCAL を観測順で接続し、Git と本文が一致する世代を COMMIT として
一つに表示する。v0.1.1（2026-08）で、LOCAL に観測時 HEAD oid（parent）を記録し、
parent と一致する Git 世代の直後に配置する血統順接続を追加した（§4.2）。親内容ハッシュ
による分岐判定、別 ancestry の自動隔離、Git から再現
できる blob の即時削除は、キャッシュ形式を拡張する後続項目とする。

## 1. 目的

akapen は Git の差分ビューアではなく、次のためのツールとする。

1. エージェントが触ったテキストを、完全な文書のまま時系列で見る
2. 人間がまだ確認していない場所を示す
3. Rendered Markdown または生ソースへ、その場でコメントする
4. 選択した本文とコメントをエージェントへ渡す

Git は必須条件ではない。Git 管理されていないファイルでも、akapen が一度観測した後の
変更はローカルスナップショットによって追跡する。

## 2. やらないこと

- unified diff の表示。word diff は独立した表示としては持たない（source モードの diff ペアの中の行内強調だけ — §6。2026-09-25）
- hunk の表示、ナビゲーション、コメントへの添付
- `git / last / off` の diff scope
- old side トグル
- staged / unstaged の区別
- Git のコミットグラフやブランチ履歴の代替
- 保存イベントを無制限に記録する履歴アーカイブ

内部で隣接する二つの文書を比較して表示位置や marks を求めることはあるが、比較結果を
hunk として UI やコメント出力へ露出しない。

## 3. 四つの独立したモデル

| モデル | 役割 |
|---|---|
| Timeline | ファイルの完全な内容を持つ、順序付きの世代列 |
| Review | 最後に人間が確認した世代から NOW までの未確認箇所 |
| Display comparison | baselineから表示中の世代までの差 |
| Comments | 特定のファイル・世代・行範囲へ付けた伝言 |

Timeline 上の現在位置、baseline、コメントの参照先は別々に保持する。
過去へ移動しただけでは baseline は動かない。過去で明示的に`a`を押した場合だけ
その世代をbaselineにする。コメントを付けても確認済みにはならない。

## 4. 統合タイムライン

### 4.1 世代の由来

各世代は完全なテキストと、次の provenance のいずれかを持つ。

| provenance | 意味 |
|---|---|
| `git` | Git コミットから再現できる世代 |
| `local` | akapen が観測し、ローカルキャッシュへ保存した世代 |
| `now` | 現在ロードされている内容 |

UI では一つの時系列として `← / →` で移動する。Git と LOCAL を切り替えるモードは
作らない。由来はラベルでのみ示す。

```text
NOW · 12/12
LOCAL · 11/12 · 14:38
LOCAL · 10/12 · 14:32
COMMIT · 9/12 · c3d4
```

### 4.2 Git と LOCAL の接続

通常は、現在の Git 履歴の先にローカル作業履歴が連なる。

```text
COMMIT A → COMMIT B (HEAD) → LOCAL 1 → LOCAL 2 → NOW
```

作業途中でコミットされた場合、LOCAL はコミット間にも存在できる。

```text
COMMIT A → LOCAL 1 → LOCAL 2 / COMMIT B → LOCAL 3 → NOW
```

Git コミットと LOCAL の内容ハッシュが同じなら同一世代へ統合する。Git から内容を再現
できるため、重複するローカル本文 blob は削除できる。途中の LOCAL は直近履歴として
保持してよい。

Git のコミット日時だけで LOCAL と並べない。世代は親の内容ハッシュと現在の Git
ancestry によって接続する。現在の ancestry へ接続できない別ブランチ由来の LOCAL は、
通常のタイムラインへ混ぜない。

#### v0.1.1: 観測時 HEAD oid による血統順配置（実装済み）

上記の ancestry 接続の第一歩として、各 LOCAL は観測時点の HEAD commit oid を
**parent** としてキャッシュへ記録する。タイムライン構築時、LOCAL は「parent と
一致する Git 世代の直後（newer 側）」に配置される。これにより、レビュー中に
エージェントがコミットした場合（A → LOCAL 1 → commit B → LOCAL 2 → NOW）も
血統どおりの順序になる。同一 parent を共有する LOCAL 同士は観測順を保つ。

**既知の劣化（ancestry 隔離までの fallback）**: parent が現在の Git 履歴のどの
コミットとも一致しない LOCAL（rebase・別ブランチ由来・非 git・旧キャッシュ由来）は、
従来どおり「Git より新しい側・観測順」に置く。この位置は血統を保証しない。分岐の
検出と隔離は親内容ハッシュを追加する後続項目で行う。

### 4.3 Git がない場合

最初に akapen が観測した内容を起点にする。

```text
LOCAL first seen → LOCAL 1 → LOCAL 2 → NOW
```

初回観測より前の内容は復元できない。キャッシュ作成後は、次回起動時に前回の内容と
現在のディスク内容を比較できる。akapen が停止していた期間の途中経過は分からないが、
前回観測時点と現在の二点は残る。

## 5. ローカルスナップショットの作成

ファイルシステムの write イベントごとには作らない。次の意味のある境界でだけ作る。

1. キャッシュに存在しないファイルを初めて開いたとき
2. `⚡ disk changed` に対して `r` で新しい内容をロードしたとき
3. 次回起動時、前回キャッシュとディスク内容が異なっていたとき
4. コメントを付けた世代を保護する必要があるとき

同じ内容ハッシュの世代は追加しない。エージェントが短時間に何度保存しても、`r` で
ロードされるまでは一つの pending change としてまとめる。

自動リロードはしない。コメント入力や選択中に文書が入れ替わらないという現在の原則を
維持する。reply mode の自動リロードは従来どおり例外とする。

## 6. 未確認変更と marks

### 6.1 baseline

ファイルごとに「最後に人間が確認した世代」を一つ保持する。NOWの未確認状態は次の比較
から求める。

```text
baseline → NOW
```

`r` を複数回行っても baseline は動かさず、未確認変更を累積する。途中の編集が元へ
戻された場合、その箇所は marks から自然に消える。

NOWで`a`を押すと現在のファイルを確認済みにする。過去のLOCAL／COMMITで`a`を押すと、
その世代をbaselineとして選び、NOWまでを未確認として再計算する。

初回観測したLOCALを最初のbaselineとする。Git管理下でも最新COMMITを暗黙のbaselineには
しない。初回観測より前から存在した変更を確認したい場合は、COMMITへ移動して`a`を押す。

- baseline を NOW へ移動
- review marks を消す
- baseline をローカルキャッシュへ永続化
- 確認済みになった中間 LOCAL をキャッシュ整理の対象にする

### 6.2 状態表示

```text
エージェントが編集
        ↓
⚡ disk changed
        ↓ r
新しい内容をロード
        ↓
● 5 blocks to review
        ↓ a
確認済み
```

`⚡` はディスクに未ロードの内容がある状態、`●` はロード済みだが人間が未確認の場所が
ある状態とする。両者を diff scope や表示モードにはしない。

表示中の世代が過去なら、同じbaselineを固定したまま次を表示する。

```text
baseline → displayed generation
```

この比較表示はNOWの未確認状態を変更しない。baselineそのものでは差が0になり、世代
ラベルを`BASELINE`にする。他の世代でもbaselineの時系列位置を`base N/M`として常時示す。

### 6.3 mark の語彙

NOWではmarksは未確認箇所を表す。過去ではbaselineに対する表示中世代の差を表す。
比較方向は常にbaselineから表示中世代へ固定する。左右移動時の一時的な
フラッシュは直前の描画との比較なので、追加・削除色を使わず中立色を維持する。

**view モード**（2026-08-13 まで両モード共通だった語彙）:

| mark | 意味 |
|---|---|
| 緑 `▌` | 現在存在する、追加または変更されたブロック／行 |
| 赤 `▌` | この位置で内容が削除された（位置のみ。内容は表示しない） |
| `>` | 現在のカーソル |

view の削除ブロックは遷移時に一度薄く表示して畳み、その後も小さな位置表示を残す。
削除の内容を view で見たいときは一つ前の完全な文書へ戻るか、`Tab` で source モード
の削除行表示（下記）へ切り替える。

```text
▌ 2 blocks removed · ← to inspect
```

**source モード**（2026-08-13 変更）: baseline との diff を行単位で全て見せる。
view で「なんとなくの差異」を感じ、source で細部を確認するという役割分担。

| mark | 意味 |
|---|---|
| 緑 `▌` | 現在存在する、追加または変更された行 |
| 赤 `▌` | baseline にはあるが表示中世代には無い行。**本文を赤の帯でインライン表示**する（緑 `▌` の帯と対になる diff ペア） |
| `>` | 現在のカーソル |

- 削除行は削除位置（anchor 行の上。EOF 削除は最終行の下）に挿入表示する。
  行番号カラムは空欄（表示中の文書に行番号を持たないため）。赤の帯は緑の帯と
  同じく行の右端まで伸び、書き換えの旧内容（赤帯）と新内容（緑帯）が一塊で読める
- **折り返し**（2026-08-13）: `▌` は行が折り返し表示されても該当行の全行に付く
  （緑も赤も同じ）。左端のマーク列が途切れないので、折り返した変更行や連続した
  変更行が飛び飛びに見えず、一続きの帯として読める

- 削除行は削除位置（anchor 行の上。EOF 削除は最終行の下）に挿入表示する。
  行番号カラムは空欄（表示中の文書に行番号を持たないため）
- **書き換え行も diff ペアとして扱い**、新内容（緑 `▌`）の上に旧内容（赤 `▌`）を
  表示する。view の `▌` と review バッジは従来どおり純減のみを数える
- 削除行は**表示専用**: カーソルは止まらず、選択はできない。
  クリックは anchor 行の選択になる（コメントカードと同じ帰属規則）
- **点灯規則**（2026-08-13）: 差分の単位は **diff ペア**。削除行は、その anchor
  行がカーソル行または選択範囲に含まれている間、明るい赤 + グレーのカーソル帯
  （全幅）で点灯する。`n` が書き換えに着地すると旧内容と新内容が一塊で光り、
  j/k で anchor 行を通っただけでもその削除が光る。ふだんは赤い帯（緑 `▌` の帯と
  対になる静的な表示）のまま
- **削除フォーカス**（2026-08-13）: `n`/`N` が**純削除**に着地したときは anchor
  行を選択せず（変更されていない行を照らさない）、`>` グリフを削除行の先頭へ
  移す。anchor 行はその間ふつうの行として描画される（カーソル帯が2本並ぶと目が
  迷うため）。この状態の `c` は削除へのコメントになり、スニペットには anchor 行
  ではなく**削除された baseline 本文**を引用する（コメント自体は anchor 行に
  紐づく）。フォーカスはカーソル移動・選択開始・Esc で解除される。
  j/k では削除行に止まれない（第2段のカーソル対応で検討）
- **コメントの原理**: コメントできるのは**画面に見えているものだけ**。紐付け先は
  常に現在文書の行範囲で、スニペットは「そこで見えていた差分の内容」を引用する
  （現存行はその本文、フォーカスされた純削除は baseline 本文。書き換えは新側の
  本文のみ — 旧側は画面に見えており、言及は人間の言葉で書く）。view は削除の
  本文を表示しないため削除へのコメントはできない。view の `n` が純削除に着地
  したときは `Tab: inspect & comment` を案内し、Tab した先の source では削除
  フォーカスが引き継がれた状態で到着する
- 削除の位置マーク（赤 `▌`）は source モードから廃止（本文そのものが出るため位置マークは不要）
- **行内の強調**（2026-09-25）: 書き換えの diff ペア（先頭から min(旧, 新) 行を組にする）
  では、行の中で実際に変わった範囲の地を帯と同じ色相で一段濃くする（新側は緑、旧側は
  赤）。カーソル帯・点灯中も残す。差分の単位は ASCII の英数字の連なりを 1 語、それ以外
  を 1 文字とし（英文は語、日本語は文字）、間に残った 2 文字以下の一致はつなぐ。
  **変わった部分が半分を超えるペアは強調しない**（行ごとの書き直しか、関係ない行どうし
  の組で、帯全体がすでにそう言っている）。view モードとコメント出力は変えない。
  入れた根拠は実測: スナップショットキャッシュの Markdown 132 本・世代の組 502 組で、
  書き換えペア 3578 のうち 17 % が「100 桁で 2 行以上に折り返し、変わった文字が 2 割
  未満」（中央値は 119 字の行で 6 字）で、世代の組の 39 % がそういうペアを 1 つ以上含む

これは「hunk を UI へ露出しない」原則（§2）の例外ではない: スコープも old side
トグルも比較対象の切替も持たず、既存の Display comparison（baseline → 表示中世代）
の削除側を位置マークから本文表示へ格上げしただけである。hunk 概念・unified diff
形式・コメント出力への添付は引き続き持たない。

コメントの所在は review mark と混ぜない。コメントカードと黄色い行番号で示す。

## 7. 表示とファイル種別

| ファイル | 表示 | review 粒度 | 履歴の供給源 |
|---|---|---|---|
| Markdown | Rendered / Source | 行 | Git（あれば）＋ LOCAL |
| その他の UTF-8 テキスト | Source | 行 | Git（あれば）＋ LOCAL |
| バイナリ | 対象外 | なし | なし |

review marks はすべて**行単位**（実装時の決定変更、v0.1 実装・README に反映済み）。
当初の「Markdown はブロック単位」案は、テーブルの 1 セル編集や段落の 1 行編集が
ブロック全体を照らしてしまうため廃止した。

Rendered / Source はモードの異なる履歴ではなく、同じファイル・同じ世代を表す二つの
表示形式である。Markdown 以外は Source のみだが、コメント、Timeline、Review の
モデルは共通にする。

テーブルは時間移動の描画では一つのレイアウトブロックとして扱うが、review marksでは
各ソース行を独立して比較する。1セル変更や行追加は対象行だけを緑、行削除はその位置
だけを赤で示す。

## 8. 操作

| キー | 動作 |
|---|---|
| `← / →` | 前／次の完全な文書世代へ移動 |
| `Tab` | Markdown の Rendered / Source を切り替え |
| `r` | `⚡` の新しい内容をロードし、LOCAL 世代を追加 |
| `a` | NOWを確認済みにする／過去ではその世代をbaselineにする。選択中なら解除 |
| `n / N` | 表示中世代とbaselineとの差の、次／前の箇所を画面中央付近へ移動 |
| `c` | 選択範囲またはカーソル位置へコメント |

`m`、`o`、diff scope、old side は削除する。変更一覧を独立した diff タブとして持たず、
ファイルピッカーへ `⚡` または `● N` を表示し、ファイル内は `n / N` で歩く。

## 9. コメント出力

コメントへ hunk、unified diff、変更前本文を補助情報として添付しない。出力は次の情報に
限定する。

```text
Revision: abc123 — commit summary
File: README.ja.md
Lines: 24-29

> 選択した本文

ここは前提を先に説明してください。
```

- NOW のコメントは `Revision` を省略できる
- 過去の Git 世代は commit id を付ける
- 過去の LOCAL 世代は `local:<内容ハッシュ>` を付ける
- コメントが付いた世代はキャッシュ GC から保護する

### 9.1 Revision 行の形式

`Revision:` 行は「`id — 説明文`」の形をとる。「 — 」より左が機械用 identity、
右が人間/LLM 用の説明文で、同一性判定は左側のみで行う。Git 世代はフル oid と
コミット subject、LOCAL 世代は内容ハッシュと次の説明文を載せる。

```text
Revision: local:<フルハッシュ> — akapen local snapshot: uncommitted state captured 2026-08-16T05:03:22Z, on top of commit 720a445 (not a git object)
```

- 説明文の `captured <UTC ISO 8601>` はスナップショットの取得時刻（キャッシュの
  固定値なので再構成しても決定的）
- `on top of commit <short 7桁>` は観測時点の HEAD oid。非 git 環境・旧メタデータ
  で parent が無い場合はこの句を省略する
- `(not a git object)` は「この id を git で解決しようとするな」という否定情報。
  受け取った LLM が `git show` を空振りしないための最重要要素
- 旧形式（`local:<id>` 裸）で保存済みのコメントも identity 部分だけで照合され、
  移行処理なしで新形式の世代へ一致する

## 10. ローカルキャッシュ

ローカル履歴はアーカイブではなく、上限のある作業キャッシュとする。リポジトリ内へ
`.akapen` 等を作らず、ユーザーのキャッシュディレクトリへ保存する。

### 10.1 保存形式

- 本文は圧縮した完全なスナップショットとして保存する
- 内容ハッシュをキーにし、同一内容は一度だけ保存する
- hunk や diff を永続化しない
- v0.1 metadata は canonical path、取得時刻、baseline、コメントによる pin を持つ
- v0.1.1 metadata は各スナップショットに parent（観測時 HEAD oid、git 環境のみ）を持つ
- 親内容ハッシュによる分岐判定・provenance の保存・別 ancestry の隔離は後続項目とする
- Git から再現できる本文 blob の即時省略は ancestry 対応時に追加する

全文スナップショットは UI と同じモデルを保てる。保存上の最適化を後から加えても、
外部へ hunk モデルを露出させない。

### 10.2 初期上限

- 1 ファイルにつき直近 32 LOCAL 世代
- キャッシュ全体で 256 MiB
- 同一内容は世代を追加しない
- 巨大ファイルはキャッシュ対象外、または baseline と NOW の二世代だけに制限

上限到達時は、古い「確認済み LOCAL」から削除する。

### 10.3 削除してはいけないもの

優先順位は次のとおり。

1. NOW
2. baseline
3. コメントが付いた世代
4. 未確認期間中の世代
5. 直近の確認済み世代
6. 古い確認済み世代

1〜4 は保護する。5〜6 は GC 対象で、6 から削除する。`a` の後は確認区間の中間世代を
圧縮できる。Git コミットと同じ内容の LOCAL は Git へ統合し、本文 blob を削除できる。

## 11. 実装移行

実装は次の順で行う。

1. 現在の完全文書タイムラインを provenance 付きの共通モデルへ変更
2. LOCAL キャッシュと baseline を追加
3. reload を LOCAL 世代作成と累積 review marks へ接続
4. Markdown はブロック単位、その他のテキストは行単位で marks を表示（実装では全ファイル行単位に変更 — §7 参照）
5. `a` と未確認ナビゲーションを追加
6. コメント出力から hunk を削除
