# akapen / ashiato git 連携 仕様案 v0.1

ステータス: 実装待ち（2026-08-08 合意済み）

## 1. 背景と目的

- 両ツールの git 対応を先送りしてきたが、主用途が**エージェントとの作業ループ内**（エージェントが編集 → 人間がレビュー → エージェントが修正）に確定したため追加する
- **akapen**: レビュー時に「元々何が書かれていたか」（変更前の内容）を正確に見せたい
- **ashiato**: git のサインを活用して「いま何をレビューすべきか」を切り出したい

## 2. 設計原則

| # | 原則 | 内容 |
|---|---|---|
| P1 | 非 git 環境の完全維持 | git 連携は「git リポジトリ内で起動した場合のみ有効」なアドオン。git なし・リポジトリ外では現行の振る舞いを一切変えない |
| P2 | 情報を増やさない | 表示要素の追加は最小限。既存の表現（DIM など）と融合させる |
| P3 | 行追跡・永続化しない | コメントは「その瞬間のエージェントへの伝言」。位置ずれは追わない。git notes 的な永続化もなし |
| P4 | スナップショット方式 | git 情報は起動時に取得。編集中のファイルと diff が食い違っても問題にしない |

## 3. akapen

### 3-1. 変更行マーク（案A）

- 起動時に `git diff HEAD -- <file>` を取得し、追加・変更行にマーク表示
- 削除行は**位置に薄いマークのみ**（内容は表示しない）。中身は 3-2 のトグルで確認する

### 3-2. old side トグル（案B）

- `o` キー: カーソルのある **hunk 全体**を変更前表示に切替（もう一度で new に戻る）
- 基準は **HEAD 固定**。ただし diff 取得は ref を引数に取る構造にし、将来の世代移動（HEAD^ 等）を後付け可能にしておく
- hunk 内で行数が変わっても表示は hunk 内に閉じる

### 3-3. やらないこと

- word diff（案C / 行内差分）
- 行追跡
- コミットへのコメント紐付け・永続化

## 4. ashiato

### 4-1. 未コミット表示

- 未コミット変更のあるファイル: 行の右側に `+N -M` を薄く表示（変更規模と未コミットの目印を1要素に融合）
- コミット済み: プラスマイナスなし + 時間表示を DIM
- バッジ・色は追加しない

### 4-2. フィルタ

- `u` キー: 「未コミット変更のあるファイルのみ」表示トグル
- `--filter` は現行のまま（パス部分一致）

### 4-3. 非 git 環境

- プラスマイナス非表示・`u` 無効（= 現行動作）

## 5. 実装上の論点（実装フェーズで判断）

- ashiato は 2 秒ごとに再スキャンするが、`git status` を毎回叩くコスト（大規模リポジトリ）→ キャッシュ戦略
- untracked ファイル（`??`）は「未コミット変更」として扱う
- diff 行数は `git diff --numstat` で取得（バイナリは `-`）
