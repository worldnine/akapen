# 2 周目 — Hedge を有効にし、本物の Jev で測る（2026-09-23）

それに **Jev の往復時間と書き換え後の再解析**を測った。文書は同じ
`showcase-slop.md` のコピーである。

## やり方（1 周目との違い）

- **ルール**: `--review-rules` に、既定の `assets/review-rules.json` から
  `filler`（0.5）と `hedge`（0.6）だけを `enabled` にした写しを渡した。
  `preamble` は入れていない（`Filler` と相関 0.98 で、同じ Unit に 3 本目の行が
  重なるだけになる）。**本体の既定は変えていない**
- **判定器は本物の Jev**（`984e3ad` の User-Agent 以降）。キャッシュは空から。
  `jev-annotate.py` の前後に時刻を刻む薄い包みを挟んだ（問いの id と秒だけを
  記録し、本文は記録しない）
- **隔離**: `XDG_DATA_HOME` / `AKAPEN_CACHE_DIR` / `XDG_CACHE_HOME` /
  `XDG_CONFIG_HOME` を scratch に向けた。コード上、捨てた記録は
  `XDG_DATA_HOME`（`src/review.rs` `DismissedStore::discover`）、解析キャッシュと
  スナップショットは `AKAPEN_CACHE_DIR`（`src/semantic_cache.rs` / `src/snapshot.rs`）
  を最初に見る。受け手の `claude -p` には元の環境を戻して渡した

  止まる（mise は自分のインストール先をそこから引く）。判定器・送信スクリプトは
  python の実体を絶対パスで呼んだ
- 受け手は 1 周目と同じ（ツールを持たない `claude -p` が全文を返し、送信
  スクリプトが書く）

```text
以下の指摘のうち `review:` で始まるものは、校正の指示である。書き換えは次の契約に従うこと。

- 指示した箇所だけを直す。直し方は、削る・縮める・統合するの 3 つだけである
- 事実・数字・固有名詞を足さない。元の文に無いものは書かない
- 具体性が足りず、削っても縮めても直らない箇所は、書き換えずに `[要: 具体例]` のような印をその箇所に残す。埋めるのは人である
- 指示した範囲の外は 1 字も触らない

ルールの定義（文中の「対象」は、指示した箇所のことである）:
- filler（削る）: 下の「対象」は、具体的なことを何も述べていない箇所である。ここを落としても、読み手が失う事実・数字・判断・理由は無い。一般論、決まり文句、それらしい前置きや締め、直前の言い換えが当てはまる。固有の事実・数字・判断・その理由を含む箇所は当てはまらない。
- hedge（縮める・統合する。足りなければ印を残す）: 下の「対象」は、断定を避けて責任の所在をぼかしている箇所である。ここを落とすと、読み手は誰が何を引き受けるのかを取り違える。「〜と思われる」「〜の可能性がある」「適切に対応する」「検討する」のように、主体・期限・内容のどれかが欠けた言い方が当てはまる。不確かさそのものを事実として述べている箇所（「未定」「確認待ち」）は当てはまらない。
```

## 直接編集 — 一覧から `e` で人が直す（2026-09-23、branch `review-edit`）

LLM に送らず、一覧の `e` で人が候補を直す流れを 3 往復した。文書は同じ
`showcase-slop.md` のコピーで、ルールは既定（`Filler` 0.5 の 1 本）、判定器は
本物の Jev、キャッシュは空から。

### やり方

- 隔離は 2 周目と同じ（`XDG_DATA_HOME` / `AKAPEN_CACHE_DIR` / `XDG_CACHE_HOME` /
  `XDG_CONFIG_HOME` を scratch へ。判定器と `$EDITOR` の python は実体の絶対パス）
- akapen は release ビルドを tmux（160×50）で立て、キーを送って操作した
- `$EDITOR` は**テスト用のスクリプト**。名前を `vi` にして、行ジャンプ
  （`+N FILE`）の一覧に乗る名前で呼ばれるようにした。受けた `+N` と終わった
  時刻を記録し、送り手が渡したバイト範囲（**その候補の Unit**）を削って終わる
- 1 往復 = 一覧のカーソルから `x j x j x j`（3 本捨てる）→ `e`（その次の候補を
  削る）→ 戻る。1 往復目の前に `R` を 1 回。2・3 往復目は、戻った一覧の
  カーソルの位置からそのまま続けた
- 数えたもの: 引き継がれた dismiss（新しい sha の記録）の行き先を、新しい版の
  解析（キャッシュ）の Unit と範囲で照らした。カーソルの行き先は、画面の `▸` の
  行と「直した位置を覆うか、その後ろの最初の候補」とを比べた。秒は `$EDITOR` が
  終わった時刻から、一覧のタイトルが `analyzing…` から `review (a/N)` に
  変わるまで（画面を 20 ms ごとに読んだ）

### 結果

| 往復 | `e` の行 | 旧の版の dismiss | 引き継いだ | 写さなかった（範囲が変わった） | 写した先の Unit が一致して候補を抑えた | 一致したが足切り未満 | **切り方が動いて一致しない** | 候補 前 → 後 | カーソル | 戻ってから出揃うまで |
