# 見出しの復帰の実測

`examples/semantic/README.md` から分けた実測の記録です。索引は

### 節に中身が残るなら見出しも残す（2026-09-22 の実測）

**結論から: 置いた合格条件はすべて満たした。** 中身が残っているのに見出しが
沈む節は 4 文書 18 ラン × 4 予算のすべてで 0 になり、節ごと沈むケースでは
見出しも沈んだままだった。予算への影響は Atom バイトの 0.68〜3.26 % で、
表示以外は 1 ビットも変わらない。

#### 何を変えたか

境界規則 4 で箇条書きを項目ごとに割ってから、見出しの Unit は「見出し ＋
せいぜい最初の項目」になり、2 つ目以降の項目は別 Unit として浮いた。結果、
**中身は残っているのに、それが何なのかを言う見出しのほうが沈む**。

これは境界規則 2「見出しは直後の内容に付く」が防いでいた状態で、
**新しい原理を足したのではなく、規則 2 の意図を「中身が複数 Unit になった
場合」について言い直した**（`jev-annotate.py` の `boundary_rule` 規則 2 と
`crates/semantic-reading/src/policy.rs`「見出しは中身に付いてくる」）。

判定器が各 Unit に `section_of`（属する節の見出し Unit）を書き、
`policy::decorate` が予算の取り合いのあとで「節の中の Unit が 1 つでも残る
なら見出しの行を戻す」を実行する。**構造だけで決まり、Jev には聞かない。**

#### 測り方

`section_of` は構文だけで決まるので、**既存の応答に後から書き足せる**。
だから「前」＝もとの応答、「後」＝同じ応答 ＋ `section_of` になり、Jev の
判定は前後で完全に同一である（規則 4 のときと同じ対照の取り方）。

基準にした応答は run キャップ版（2026-09-21）の 18 ラン。**`PRESUPPOSES` が
入る前の応答**なので、二段台帳の一段目は核だけになる。前後で同じ応答を使う
以上、比較そのものはこれで成り立つ。

#### READ 1 % と 5 % で数字が動かない文書がある

`demo.md` と `design` と業務議事録は、1 % と 5 % で結果が同じである。台帳が
二段になってから、低予算で残るのは**一段目（核とその閉包）だけ**で、そこは
Budget の関数ではないため。二段目が 1 つも買えない予算のあいだ、表示は
まったく動かない。`README.md` だけは 5 % で二段目が動き出している。

#### 入れ子 — 低予算の見え方は実際に変わる

**子の節に中身が残っていれば、親の見出しは戻る。** `###` が戻れば `##` が
戻り、それが `#` を戻す。3 階層を持つのはこの `README.md` だけで、READ 1 %
での内訳はこうなる（4 ラン中の 1 本）。

```text
前:  ##×1 ###×1                  （2 本）
後:  #×1 ##×2 ###×3              （6 本）
```

業務議事録（2 階層）でも同じ形で、READ 1 % では表題の `#` が前は 1 度も
立たず、後では 6 ラン中 6 本とも立つ。

**これは正しい見え方だと判断した** — 背骨は骨格そのものなので、READ 1 % で
文書の骨格が立つのは求めていたものである。ただし**低予算の見え方が変わった
ことは事実**なので、数字を上に残した。

#### やっていないこと

- **列挙の虫食いには触っていない。** 「しょうもない決定事項は個別に沈んで
  よい」は注文どおりの仕様である（`lists-and-run-cap.md`）
- **閾値は足していない。** 判定は「節に残る Unit があるか」だけ
- **Jev に聞いていない。** 節の境界は構文から決まる

#### 確認したこと

4 文書（`demo.md` / `design/semantic-reading-layer.md` / この `README.md` /
業務議事録 22.7 KB）× 18 ラン × READ 1 / 5 / 30 / 100 %。表示状態は
`atom-states`（`policy::decorate` そのもの）。応答は run キャップ版の既存の
ランで、`section_of` だけを後から書き足したものと素の応答を突き合わせた。
採取スクリプトと生ログは証拠ディレクトリの
`runs/2026-09-22-heading-follows-content/`。

業務 `CLAUDE.md` 45.6 KB は**測っていない** — 凍結した本文が証拠ディレクトリ
に残っておらず、Atom を作り直せないため。
