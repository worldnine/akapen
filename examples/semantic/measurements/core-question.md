## 何を直したか

[`unit-granularity.md`](unit-granularity.md) の「気づいたこと」1 — **核の問いが、いまの問いを見ていなかった。**
核の Choice の文面（判定器の `CORE_INSTRUCTIONS`）は「このまとまりの中で、これを読み飛ばすと要点を失うのは
どれか」で**問いにかかわらず固定**だった。numbers で光った Unit でも、光る一文は「その Unit の要点」になる。

直したあとの instructions（`CORE_INSTRUCTIONS` + `CORE_FRAME`、組むのは `core_instructions(text)`）:

```text
次の選択肢は、この文書の中の連続した 1 つのまとまりを構成する各部分の本文である。それぞれを「対象」として下の説明に照らしたとき、**いちばんよく当てはまる**のはどれか。

――― 説明 ―――
{akapen が送ってきた問いの文面 — スコアのラウンドと同じもの}
―――――――――
```

- スコアは Unit を「対象」として、核は Unit の各部分を「対象」として、**同じ文面**に照らす。問いの文面はどれも
  「下の「対象」は、…」で始まるので（定型 5 本・自由入力の型・Review のルール 3 本。テストで固定した）、枠の側で
  「それぞれを「対象」として」と先に言えば同じ文面がそのまま読める
- **1 段のまま。** 問いの文面は akapen が送った入力で、前のラウンドの答えではない。判定器に問いごとの文面は書いていない
- `core_fits` / `dry_run` も同じ instructions で見積もる。境界は触っていない（`BOUNDARY_CACHE_VERSION` もそのまま）

**直したあとも、akapen 側の解析キャッシュは古い核を返す。** キャッシュの鍵は（コマンド行・文書・問いの文面）で、
判定器の中の文面は入っていない（`src/semantic_cache.rs`）。新しい核を見るには `akapen --semantic-cache-clear`。

## 何を比べたか

| 案 | Unit | 核 | 今回走らせたか |
| --- | --- | --- | --- |
| **A** | 構造ルール + Jev の境界 | 旧文面（固定） | いいえ（前回の応答） |
| **A'** | **前回の A と同じ**（境界キャッシュを写して固定） | **直した文面** | はい |
| **B** | Unit = Atom（文ごと）。境界 0 問・核 0 問 | 無し | いいえ（前回の応答。核のラウンドが無いので今回の変更の影響を受けない） |

- 対象・問い・凍結コピーは前回と同じ（6 文書、定型 5 本、`core_floor: 0.20`）
- **A' は前回の A の境界を写して走らせた。** 走らせる前と後の両方で、Unit が前回の A と一致することを 12 組
  （6 文書 × 2 ラン）× 5 問で確かめた。60 回すべてで境界のラウンド 0 問・`boundaries_cached: true`・送れなかった
  question 無し。**A → A' の違いは核の問いだけ**（とスコアのラウンドの Jev の揺れ）
- B の 60 本すべてでラウンドが marks だけ（核・境界無し）であることを確かめた
- **A' は 6 文書 × 5 問 × 2 ラン = 60 回、失敗 0、15.19 円**
- 光った Atom はすべて `atom-states`（`marks::mark`）で数えた。前回の A・B の光も同じバイナリで引き直して 240 件とも一致
- B は同じつまみで光る本数が多いので、前回と同じく **(i) つまみ 20 % / 100 %** と **(ii) B を A' の本数に揃えたもの**の両方で見た

## 8. 人が判定する表

業務議事録と `b1` × 定型 5 問で、つまみ 20 % の **A' のラン 1** と **B のラン 1（A' の本数に揃えた）** の片方だけが

載せていない。

- 表は本文を含むので証拠側の `judge/` にある。**ユーザーに渡すのは案を伏せた版**（問いごとに行を混ぜ、通し番号。
  対応表は別ファイル）。案の列つきの版は答え合わせ用
- 同じ結果を画面でも見られるよう、A' / B そのもの / B を A' の本数に揃えた派生版の fixture を 30 本用意した。
  判定器の応答 JSON は Atom の位置を持たないので `--semantic` にはそのまま渡せず、`SemanticDocument`
  （要求 JSON の atoms + 応答の units + `source_sha256`）に組み直してある。30 本とも `FixtureProvider::from_path`
  で読め、つまみ 20 % の光り方が表と一致した
- `AKAPEN_SEMANTIC_CMD` を export している環境では `--semantic` と `--semantic-cmd` の相互排他で断られるので、
  起動コマンドは `AKAPEN_SEMANTIC_CMD= akapen … --semantic …` の形にした（`src/config.rs`）

**判定は付けていない。**
